How a payment is scored

Pipeline

Data

Simulated UPI traffic

6,892 accounts, 75,001 payments, 7.0% fraud across 5 patterns.

Features

44 point-in-time features

Built only from history before each payment. Same code in training and serving.

Model

XGBoost + isotonic

Calibrated fraud probability, explained with per-payment SHAP.

Fusion

0.2 rule · 0.6 ML · 0.2 graph

Fused score plus confidence from engine coverage and agreement.

Action

Intervention ladder

inform → warn → verify → hold → restrict → escalate.

Inputs

Data and features

Dataset

  • Normal traffic: log-normal amounts, Pareto-weighted activity, realistic hour-of-day curve.
  • Fraud patterns: scam_recipient, mule_network, layering_chain, account_takeover, gambling_network.
  • Hard negatives: large_new_payee, group_collection, innocent_bystander.
  • 30-day burn-in, 6% of normal accounts opened mid-window, 30–50% of fraud accounts aged or recruited, so account age alone can't give away the label.

Method

Training

  1. Drop the burn-in, then split chronologically 60 / 20 / 20: train 32,845, validation 10,948, test 10,949 rows.
  2. Grid search XGBoost over depth {3, 4, 6}, learning rate {0.05, 0.1}, min child weight {1, 5}, with early stopping on validation PR-AUC. No class reweighting, so probabilities stay honest.
  3. Fit isotonic calibration on validation, so a score of 0.7 means about 70% of such payments are fraud.
  4. Set the alert threshold at the lowest calibrated score that keeps validation false positives at or under 1% (0.15).
  5. Train an Isolation Forest (300 trees) on normal traffic only, reported as a percentile of normal anomaly scores.
  6. Evaluate once on test: per-pattern recall, look-alike false positives, calibration, leave-one-scenario-out, and a feature-tier ablation.

Next iteration

What gets us to the targets

Look-alike-aware features

Add signals that separate real group collections and large first payments from scams: sender-circle overlap with the payee, round-amount clustering, repeat payments inside a known group, payee tenure as a merchant.

large new payee ≤ 10% · group collection ≤ 8%

Hard-negative training

Oversample the legitimate look-alikes in training and track their false-positive rate as a first-class validation metric next to PR-AUC.

precision at alert ≥ 90%

Two-hop graph features for mules

Move beyond one-hop counts: 2-hop fan-in, shared-device clusters, time-to-forward along a chain, and node embeddings from the payment graph.

mule recall ≥ 92% · unseen ≥ 85%

Receiver-level gambling profile

Aggregate at the operator: inflow-only behaviour, short lifespan, many small round bets, payout bursts. Individual bets look ordinary; the operator doesn't.

unseen gambling recall ≥ 60%

Exposure decay for bystanders

A single ordinary payment to a later-flagged account should fade quickly. Weight exposure by amount, recency and repeat contact.

bystander FPR ≤ 3%

Rolling-window validation and recalibration

Replace the single split with rolling-origin folds, and refit the calibrator on the most recent window so it tracks the live fraud rate.

mid-bucket calibration 58–65% · Brier ≤ 0.006

Investigator feedback loop

Feed confirmed cases back as labels, so the known-fraud rule and graph exposure can be weighted from data instead of a fixed floor.

fused PR-AUC ≥ 0.96 · escalate recall ≥ 45%

Drift monitoring and threshold intervals

Track feature PSI and score distribution weekly, and bootstrap confidence intervals for the top ladder thresholds, which rest on few legitimate rows.

verify FPR held ≤ 1.0%
